# Independent finite selected-witness replay through n=11

Date: 2026-09-05.
Status: **MACHINE_CHECKED_FINITE_CASE_ARTIFACT_REVIEW_PENDING**.

No general proof or counterexample is claimed. The new n=11 computation is
review evidence, not an automatic promotion of the repository's accepted
n<=8 bound. Independent code review, geometric review and preferably a
second full n=11 implementation remain required before promotion.

## Search domain and exhaustive coverage

Label a hypothetical strictly convex n-gon by its counterclockwise boundary
order 0,...,n-1. For every center, enumerate all four-subsets of the remaining
n-1 labels. Every counterexample has at least one such selected-row system,
even when a distance class has more than four witnesses or a vertex has
several rich radii. Radii may vary and incidences need not be reciprocal.

For n=11, center 0 has exactly binom(10,4)=210 possible rows. The stored
artifact exhausts every one of these slices, indexed 0,...,209 in the
lexicographic combination order used by `exact_search.cpp`. The other centers
are selected by minimum remaining values, with deterministic tie-breaking.
No cyclic-order normalization is imposed on a fixed abstract pattern: labels
already denote the actual boundary order, and all selected rows are searched.

The solver terminates early upon a survivor or an explicit node limit. A
slice is accepted as an exhausted exclusion only when its run reports both
`complete=true` and `survivor=false`. The full stored n=11 run used no node
limit; no timeout result is accepted as an exclusion.

## Necessary predicates, and why they are sound

**Incidence and crossing.** Two selected circles at distinct centers cannot
share three distinct witnesses. If they share exactly two witnesses u,v,
the two centers lie on the perpendicular bisector of uv. Strict convexity
forces them onto opposite sides of uv, so the center chord crosses uv.
For a fixed witness pair, there are at most two possible centers on its
perpendicular bisector. Hence pair-usage is at most two. Counting the three
co-witness pairs generated by each row containing a fixed label gives
3*indegree <= 2*(n-1), the indegree cap used by the solver. These are
necessary bounds, not a Euclidean realization test.

**Selected-distance quotient.** An unordered pair indexes an ordinary
Euclidean distance. The four spokes in a selected row are equated by a
disjoint-set structure. For a<b<c<d, strict convexity implies

    d_ac+d_bd-d_ab-d_cd > 0,
    d_ac+d_bd-d_ad-d_bc > 0.

These follow by splitting the crossing diagonals at their intersection and
using strict triangle inequalities. Reduce each integer coefficient vector
through the selected-distance quotient. A zero vector gives 0>0. Two vectors
that are positive scalar multiples of exact negatives also give a
contradiction. Primitive integer normalization and exact key comparison
implement these tests. Hash collisions are resolved by comparing complete
keys, not by treating hashes as certificates.

The packed representation uses ten bits per nonzero entry, at most four
entries, and a separate length field. The compile-time bound n<=16 ensures
that a pair index fits in the seven bits preceding its three-bit coefficient
code. At n=11 there are only 55 unordered-pair labels. No floating-point
number is used in any prune.

**Strict turn packing.** At a center i, let selected offsets be
0<a0<a1<a2<a3<n. The existing equal-distance turn lemma forces internal turn
strictly greater than pi/2 on each of the following arcs:

    i+1,...,i+a1-1,
    i+a2+1,...,i+n-1.

For the first, equality of |u| and |u+v| gives u.v=-|v|^2/2<0. If all the
intervening directed edges rotated through at most pi/2, all cross dot
products between the two edge sums would be nonnegative, a contradiction.
Reverse the arc for the second inequality. See the repository's
`docs/turn-inequality-lemma.md` for the complete indexing convention.

Four pairwise disjoint such strict arcs are impossible because their turns
would sum to more than 2pi. Circular intervals are tested by trying every cut
and greedily scheduling the non-wrapping intervals by earliest finish. The
oracle instead enumerates all four-subsets of intervals. This filter uses the
strict geometric inequality, not only the repository's weaker closed
half-space relaxation.

All these obstructions persist after assigning further rows. Exhaustive
branching with these prunes cannot discard a realizable counterexample,
provided the implementation and stated geometric lemmas are correct.

## Validation actually performed

The finite source used for the complete run is preserved byte-for-byte:

    SHA256 c54766f191a022fbc0f8f653266f9373ef02fe8f4de37fcd342848a06877ab48

With both metric and turn prunes disabled, the same brancher enumerates
exactly 184 complete n=9 incidence/crossing/count systems, agreeing with the
repository's stored frontier. This calibration visited 100,818 nodes.

`oracle.cpp` uses deliberately different representations: explicit set
intersections instead of compatibility bitsets, whole-class relabeling
instead of the solver's distance DSU, maps/sets of coefficient vectors
instead of packed hash-table keys, and brute-force four-interval enumeration
instead of circular greedy scheduling. With seed 970905 it checks 7,236
partial states at n=9 and 9,906 at n=11, with zero predicate mismatches.
Both compatible-prefix and unconstrained-conflict samples are included.
This is a predicate cross-check, not an independent full n=11 search.

A sanitizer build, exact geometric-fixture checks, source-hash validation,
and the commands recorded in `validation.json` provide additional defensive
checks. They do not constitute external independent review.

## Reproduce

Run from this directory, using Python 3.10+ and a C++17 compiler:

    python validate.py
    python replay.py --quick
    python replay.py --full-n11 --jobs 8

`validate.py` verifies stored coverage, counters, hashes, the rational
turn identity and exact controls. It does **not** rerun the exhaustive search.
`--quick` compiles and runs both oracles, the n=9 incidence calibration,
the complete n=9 and n=10 metric/turn searches, and n=11 slices 0,1,209.
`--full-n11` compiles and regenerates all 210 slices, comparing every stored
integer counter and rejecting a timeout, abort, survivor or mismatch.
Per-slice durations are not compared, because they depend on hardware.

The complete repository `make verify-fast` and `make verify-artifacts` were
not run in this environment: this packet was built from connector-read source
without a full local repository checkout, and local network/DNS access did
not permit obtaining one. The packet's standalone checks are recorded
separately rather than being presented as repository-wide CI.

## Claim boundary

The search supports a candidate computer-assisted exclusion at n=11. It does
not check n=12, prove the extraction bridge in `proofs.md`, certify a general
solution, or verify the 66-point partial construction independently. The new
geometric radius-descent proof was not used as a finite-search prune.
